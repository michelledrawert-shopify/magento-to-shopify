Five ways to move store data

Shopify documents five ways to move a store's content, in order of technical complexity, simplest first:

  1. Copying and pasting content, such as policy pages, into the new store
  2. Exporting data to CSV files and importing them into Shopify, which some data types do not support
  3. A migration app from the Shopify App Store
  4. A Shopify Partner who manages the migration
  5. A custom migration built on the Shopify API, in-house or by a partner

Shopify's free Store Migration app imports product and customer data from Square, WooCommerce, Etsy, Wix, Amazon, eBay, Clover and Lightspeed R/X (Vend). Magento is not on that list.

Matching the route to the store

The best route depends on catalog size, data complexity and technical resources. Shopify's Magento to Shopify migration guide pairs each store profile with a route:

Store profileRouteWhen it fits
Small catalog (under 500 SKUs), simple pricingManual or CSV file importLimited budget, straightforward products, no custom attributes
Medium catalog, standard product typesMigration appSpeed without heavy development involvement; standard Magento data structures
Large catalog, configurable products, tier pricingMigration service or agency partnerComplex attribute mappings, customer group pricing, multi-store content
Multi-store, B2B pricing, custom ERP integrationsCustom API migration with a partnerHeavy customization, unique data relationships, ERP sync requirements

Automated does not mean hands-off. Data mappings still need validation before the run, the output needs testing, and the final cutover needs a planned downtime window. A dry run into a development store allows testing and fixes before the live migration.

What each data type supports

Each data type has its own set of bulk migration options.

DataBulk migration options
ProductsProduct CSV import, migration apps
CustomersCustomer CSV import, migration apps, Customer API
Historical ordersMigration apps, Order API, Transaction API
Gift cards, certificates and store creditsMigration apps, GiftCard API
BlogsMigration apps, Blog API, Blog Article API
Pages (shipping policy, contact and other pages)Migration apps, Page API

Import order matters. Products come first, then customers, then historical orders, so that each order connects to the right products and customers. Staff set to receive new order notifications get an email for each imported historical order unless those notifications are deactivated for the import.

Magento data that needs a plan

Some Magento data has no direct Shopify equivalent:

  • Customer passwords cannot be migrated in a usable format. The alternative is account activation emails or password reset prompts after launch.
  • Configurable products map to Shopify variants, though complex configurations may need manual review.
  • Custom attributes become Shopify metafields, mapped before migration rather than after.
  • Tier pricing and customer group pricing in heavy use calls for a review of whether Shopify's B2B features cover the requirement. B2B is available on the Basic, Grow, Advanced and Shopify Plus plans, and the capabilities vary by plan.
  • CMS blocks and widgets have no direct parallel; key content is rebuilt natively in Shopify.
  • URLs in Magento often carry .html extensions and category paths, while Shopify uses a flat structure such as /products/product-handle. Every indexed URL needs a 301 redirect.
  • Faceted filtering by attribute works differently from Shopify's collection filtering, so filterable attributes need a translation plan.

Working with a partner

The Shopify Partner Directory has a store migration category, filterable by location, partner tier, industry and price range.

Factors that typically point to a dedicated migration service:

  • High SKU counts with complex variants
  • Multiple markets, currencies or storefronts
  • ERP, OMS, WMS or PIM dependencies
  • Subscription, loyalty or returns workflows
  • Regulatory and security requirements

Starting-point deliverables for a Shopify Plus migration statement of work:

  • Discovery and data audit
  • Data mapping document, with transformation rules for fields that need restructuring
  • At least two migration runs (staging and production), each with documented results
  • QA plan: automated validation checks, a manual sampling protocol and business sign-off criteria
  • Cutover plan: data freeze windows, DNS changes and integration switchovers
  • Rollback plan for critical issues during cutover
  • SEO deliverables: 301 redirect map, canonical URL strategy, metadata mapping and post-launch crawl verification
  • Training on the migrated data in the Shopify admin
  • A post-launch support window, typically 2 to 4 weeks

Custom builds

The GraphQL Admin API supports bulk imports. Mutation inputs go into a JSONL file, one input per line. The file is uploaded through the stagedUploadsCreate mutation and run with bulkOperationRunMutation as a single asynchronous operation, and the results come back as a JSONL file. The mutation runs once for each line of the input file.

Limits to plan around, from the bulk imports documentation:

  • The JSONL file can't exceed 100 MB.
  • An operation must finish within 24 hours, or it is stopped and marked failed.
  • Lines are not processed in order, so an import shouldn't depend on line sequence.
  • Errors are reported per line in the results file. The whole operation is marked failed only for critical system errors.
  • From API version 2026-01, up to five bulk mutation operations can run per shop at once.
  • Result file URLs expire after one week.
